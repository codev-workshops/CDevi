CDevi සීදේවි — demo pages

Each page is a standalone screen built only from css/cdevi.css. Use them as reference implementations; the component gallery is at docs/index.html.

  1. InboxHome. Decisions first, then running work, then finished runs waiting for review. Gate rows carry the exact question being asked so a decision can be made from the list. The right panel keeps the day's numbers and a one-line reminder of policy.
  2. Spec session — Spec Kit elicitation, analysis and planningWhere a change begins. The stepper follows Spec Kit's loop; the developer picks the agent, key and runtime once for the whole session. Clarifying questions arrive as cards. Delegate all is disabled until analyze has passed.
  3. New taskReached from Delegate all (pre-filled from tasks.md) or as an ad hoc task, which requires a reason. Every default comes from the repository settings so a returning developer only reads and confirms.
  4. Run — transcript with a decisionThe live surface. Identity and budget in the header, the agent's words as prose, its tools as a compact log grouped by step, and the approval card in the flow where it was raised. The panel carries the gate checklist so the outcome of the run is never out of sight.
  5. Run — changesFile list on the left of the main column, diff on the right. Effect classes from the tool log are carried into the file list so a reviewer can see which files the agent only read.
  6. Review and evidenceThe promise made visible. Every required gate with its source and trust; a local test result is shown as needing CI in this workspace; the agent's own summary sits below the checklist and is labelled as not evidence. Approve and merge stays disabled until the acceptance checklist is complete.
  7. Agents & keysEvery credential the user can see, with the facts that matter. Nothing beyond the fingerprint is ever displayed. Validation is part of saving; laptop-held keys appear with a fingerprint only, marked as never uploaded.
  8. Repository settingsHow the sandbox is built, how tests are proven, what the agent may reach, and the defaults the composer will pre-fill, including the default runtime.
  9. UsageModel cost is shown and attributed to keys, people and repositories, never billed by CDevi. Cloud minutes are the platform's own meter; laptop minutes are counted but free.
  10. Local runtime — the cdevi CLIThe same runner and adapters on the developer's laptop. Keys are read from the environment and never uploaded; the web inbox shows the run within seconds; questions can be answered in the terminal or from the web inbox.
